First release. How each part works is in [ARCHITECTURE](../ARCHITECTURE.md), the flags and
outputs in [CLI](../CLI.md), the measurements in [BENCHMARKS](../BENCHMARKS.md) and
[LEADERBOARD](../LEADERBOARD.md), the security model in [SECURITY](../SECURITY.md).

### Engine A: universal instant search
- Literal, regex (linear time, size-limited), identifier (all casings, digit/acronym aware),
  fuzzy/approximate (Myers bit-parallel, pigeonhole prefilter), multiline, inverted, whole-word,
  smart-case matching; context lines; `-c`, `-l`, `--max-count`, `--max-results`.
- Parallel ignore-aware traversal (`.gitignore`, `.ignore`, `.rgignore`, global excludes, hidden,
  symlinks, depth and size limits, type globs); per-file batched streaming; Ctrl-C and broken-pipe
  cancellation; deterministic `--sort`; JSONL output (schema 1); exit codes 0/1/2/130.
- Differentially tested against ripgrep on random corpora and patterns: zero disagreements.
- `-e PATTERN` (repeatable) for several patterns (`-e '->'` works); each line of a multi-line
  match gets its own line number, and in colour its path.
- `-P` / `--pcre2`: PCRE2 syntax (look-around, backreferences), stopped by PCRE2's match limit
  on exponential patterns. PCRE2 is the `pcre2` cargo feature, on by default; a build without it
  refuses `-P` ([CLI](../CLI.md)).
- `-z` / `--search-zip`: zip and tar members (`archive.zip{member}`) and compressed files, with a
  64 MiB cap on one expanded line and at most 64 KiB of a tar member's long name
  ([CLI](../CLI.md)). A compressed file whose text has a NUL reports a binary
  match, as ripgrep does.
- `--fuzzy` patterns up to 4096 characters, an edit being one character (`naïve` is one edit from
  `naive`); `grep --index --fuzzy` agrees with the walk. `--fuzzy-regex[=N]`: a regex within N
  edits, with the column, `--json` spans and colour at the true start of the match. `-w` or `-U`
  with either fuzzy mode is an error.
- `grep --index` searches the text index, and `grep --index --update` refreshes it (changed files
  only) first. Like the walk, it skips the file standard output writes to.
- Smart case counts only letters that stand for themselves (`-S '\Sfoo'` is case-insensitive, as
  in ripgrep; a letter written by its code point, `\x41`, counts) and folds only a pattern with a
  literal and no uppercase letter; of `-i` and `-S` the later wins, and `SCRUTATE_GREP_SMART_CASE`
  applies when neither is given.
- `^` and `$` are line anchors in every mode, as in ripgrep: `^(a|aa)+$` over the patho corpus
  takes 13.1 ms on macOS, ugrep 21.3 ms (LEADERBOARD.md, macOS warm, `patho/backtracking trap`).
- Output follows ripgrep 15.2.0:
  - Paths print as given (`./a.txt` for `.`); with one file as the only path, lines leave its name
    out; `-H` and `-I` choose. On Unix a backslash in a file name stays in the printed path; only
    Windows turns `\` into `/`, and prints no `\\?\` prefix (`C:/x`, a share as `//server/share`).
  - With `-A`, `-B` or `-C`, a line `--` separates groups; `-A` and `-B` win over `-C` in either
    order. An option given twice takes its last value (`-m1 -m2`, `-C1 -C3`).
  - A CRLF line prints with its `\r`, in streamed, sorted and `--max-bytes` output and in colour;
    `--json` and MCP text carry no line end.
  - A line that is not UTF-8 prints as its own bytes in plain output; `--json` text holds U+FFFD.
  - `--json` spans and colour leave out the empty matches ripgrep leaves out. In `--json`, `spans`
    and `column` count bytes of the printed `text`, as do the Python bindings' `Match.spans` and
    `Match.column`.
  - A file with a NUL byte is read as ripgrep reads it on the same platform: line output prints
    `binary file matches (found "\0" byte around offset N)` (a `binary` record with `--json`), and
    a walked file with a NUL byte is left out of `-c` and `-l`.
  - `-c` with `-U` counts as ripgrep does, and `-c` with `--max-count` stops at the limit. `-c` and
    `-l` give one record per path given. With `-l`, `--stats` says `N of M files match`, and the
    JSON summary gives `"matches": null`.
  - `--max-results N` stops at exactly N matching lines, after the after-context of the Nth match
    (a match inside that context prints as a match and does not count toward N); `-m N` is a
    per-file limit. `--stats` and the JSON summary of a search stopped by `--max-results` count
    only printed matches.
  - `--sort` prints in the order of `rg --sort path`, also with `--max-results N`.
  - One difference by choice: line numbers print by default to a pipe or file too, where ripgrep
    prints them only to a terminal; `-N` turns them off.
- Exit codes: a search path that does not exist is a warning and exit code 2, and the other paths
  are searched. A path that could not be searched (an unreadable file or directory, a dangling
  link, a loop `-L` follows, an archive member it stops in, PCRE2's match limit) gives exit 2
  after any matches. With no path, a search that searched no file, because `-g`, `-t`,
  `--max-depth` or an ignore file left out every one, prints `no files were searched` and exits 2.
  A failed write of the output other than a closed pipe is an error with exit code 2. Files that
  could not be searched, or not to the end, are named in warnings.
- `grep foo . > out.txt` skips `out.txt`, as ripgrep does.
- With no path, a pipe or file on standard input is searched (`-` names it; label `<stdin>`). A
  named pipe, `<(...)` or `/dev/stdin` given as a path is searched, and a link to a directory is
  walked.
- A `-g` glob is taken whole, commas included (`-g '*.{txt,log}'`); `SCRUTATE_GREP_GLOBS` and the
  configuration file's `globs` split at commas outside braces. `-t TYPE` matches after the ignore
  rules, as ripgrep's `--type` does, and a type includes the extensions its language shares with
  another, told apart by content (`-t cpp` takes `.h`, `-t objc` takes `.h` and `.m`).
- A pattern or option value that is not UTF-8 is an error (a path may be any bytes). With `-e`, a
  first path that is not UTF-8 is searched as a path. On Unix a non-UTF-8 file name prints as its
  own bytes in piped output, and `--json` adds `path_bytes`. The index commands and MCP tools,
  and `scrutate grep` on a terminal, print a control character or bidi mark in a name as an
  escape; piped, `scrutate grep` prints the name as is, as grep and ripgrep do
  ([CLI](../CLI.md#conventions)).
- `-n` is accepted and `-N` drops line numbers; `-j`, `SCRUTATE_THREADS` and `threads` stop at
  256. `--type-list` and `--version` need no pattern.
- On Linux, files and directories on `/proc`, `/sys` and the other kernel pseudo filesystems are
  read to the end.
- Text not on disk can be searched (`Paths::Memory`), with the output a file of the same bytes
  gives; one module (`source.rs`) reads every kind of source. Engine A has one way in,
  `instant::search`.
- Threads: one scheduler with one module of thread rules runs every walk and file list. Small
  roots are walked on the calling thread and a one-file search starts no thread. A file of 64 MB
  or more is searched on every search thread as ranges of whole lines, output in file order. On
  macOS a many-file search runs one thread per performance core, a walk whose reads come from the
  disk adds threads up to 24, and concurrent searches of one user share the threads, since the
  kernel serves about four file-reading threads at full speed (`SCRUTATE_GREP_DEBUG=1` shows the
  count). On Linux a tree read from the disk gets up to 64 threads. `SCRUTATE_COUNT_KEY=N` keeps a
  count of big searches apart from the one the user's other searches join
  ([CLI](../CLI.md#engine-a-grep-alias-g)).
- Speed, as measured for this release:
  - Start-up on macOS on Apple silicon (a directory with one file, no match) is 3.0 ms median,
    GNU grep 2.7 ms, ripgrep 6.3 ms (BENCHMARKS.md, Startup): system functions a search never
    calls are bound lazily, a grep-only argument parser skips clap, and the executable is linked
    with an order file (`crates/scrutate/startup.order`, from `tools/order_file.py`). The glibc
    Linux release binaries are laid out the same way. `-F` with one literal skips the regex
    engine.
  - `return` in the Linux tree (1,299,381 matching lines): 630 ms on macOS (ripgrep 1,146 ms) and 182 ms in
    a 5-CPU Linux VM (ripgrep 304 ms) (LEADERBOARD.md, warm, `linux/very many matches`).
  - Cold cache, the Linux tree: 1,315 ms on macOS (ripgrep 1,791 ms; LEADERBOARD.md, macOS cold,
    `linux/literal`), 355 ms in the 5-CPU Linux VM (git grep 1,200 ms, ugrep 1,284 ms;
    LEADERBOARD.md, linux-aarch64 cold, `linux/literal`).
  - A case-insensitive literal (`-i`, `-F -i`, `-S`) finds candidate lines without the regex
    engine, and a search for a long literal does not slow on near misses.
  - A regex whose matches all end in one of a few literals (`\w+_(suspend|resume)\(`) finds
    candidate lines by those literals, and one whose every match starts a line with one of a few
    literals looks only at those line starts.
  - A large file with no line breaks is read into one buffer, each search thread filling its own
    part: one long line in 32.0 ms on macOS, ugrep 38.8 ms (LEADERBOARD.md, macOS warm,
    `patho/long line`).
- Memory, as measured for this release: peak resident memory for a common literal on the small,
  big and massive corpora 10.0, 12.3 and 12.2 MB (ripgrep: 7.2, 9.2 and 13.3 MB; BENCHMARKS.md,
  CPU time and peak memory). Lines over 64 KB are written uncopied, their UTF-8 checked 256 KB at a
  time.
- The walker is its own crate, `scrutate-ignore`, a modified copy of `ignore` 0.4.34
  (`Unlicense OR MIT`) with eleven changes listed in `vendor/ignore/README.md`, so a crate built
  from crates.io walks with the same code ([ARCHITECTURE](../ARCHITECTURE.md)).

### Engine B: code intelligence
- Incremental index (SQLite + memory-mapped segments), content hashing, atomic updates,
  compaction, GC, corruption detection and self-healing rebuild, schema/model versioning,
  multi-process safety, `check` command. The on-disk index is a cache with its own schema
  version: an index of another version is rebuilt once by itself. An older scrutate reads an
  index a newer one built when only the parsing rules are newer, and otherwise refuses it with
  exit 2; `scrutate index --force` rebuilds it.
- 61 tree-sitter grammars in the default build and 13 more with `--features extra-langs`, each
  verified by a snapshot sample; keyword heuristics for grammar-less languages, windows for
  everything else; imports and call edges ([LANGUAGES](../LANGUAGES.md)). GDScript (`.gd`) is
  in the default build (`tree-sitter-gdscript` 6.1.0, MIT). HTML and XML
  are not parsed.
- A `[[language]]` table in `.scrutate.toml` or your configuration file adds a language without a
  build: extensions, comment marks and one regular expression per definition kind. Its files get
  symbols, outlines, documentation and ranked hits, and `grep --type` and `languages` know it; a
  bad table is one error with the file and line, exit 2. The patterns of every table share one
  regex size budget, and an extension a built-in language claims for a file name is refused
  ([LANGUAGES](../LANGUAGES.md), [CLI](../CLI.md#custom-languages)).
- Index commands: `symbol`, `callers`, `callees`, `refs`, `outline`, `deps`, `rdeps`, `similar`,
  `dupes` (exact + MinHash/LSH near-duplicates), `tsquery` (tree-sitter structural search),
  cross-repository `search --also`.
- `scrutate read PATH [--start N] [--end N]` and `read --symbol NAME`: the MCP `read_code` tool
  on the command line. `read --symbol NAME --history [N]` and `read_code`'s `history` list the
  last commits that changed each definition's lines, newest first, through renames and
  uncommitted edits, for the first 10 definitions shown; in a shallow clone it marks where the
  history is cut. It needs git 2.25 or later.
- `scrutate map [PATH]` and the MCP tool `repo_map`: the files that define code, ranked by
  PageRank over calls and imports, each with its 5 most called definitions.
  `scrutate path FROM TO [--depth N]` and the MCP tool `call_path`: the shortest call chain
  between two definitions; no chain exits 1 ([CLI](../CLI.md)).
- `scrutate dead [PATH]` and the MCP tool `dead_code` list the definitions nothing in the
  repository uses, leaving out each language's entry points (`main`, tests, `#[no_mangle]`,
  Python `__x__` names, exports, Ruby methods Ruby calls itself and the like); a name some line
  holds that the resolver ties to nothing is listed as undecided, with the reason.
- `scrutate impact [--base REV] [--staged] [--depth N]` and the MCP tool `impact`: from the git
  diff to the definitions it adds, edits and deletes, their callers with distances (3 steps by
  default), the test files to run, and the change's findings: the duplicates it adds of code the
  repository has and the changed definitions no test reaches. A bad revision is exit code 2
  ([CLI](../CLI.md)).
- `scrutate review --base REV [--head REV]` reports a pull request: `impact` between the two
  commits and the duplicates the head adds, as a PR comment (`--format markdown`), JSON or a
  GitLab Code Quality report, which the GitLab template saves as the job's `codequality` report.
  Only a changed function, method, class, struct, trait, interface, type, enum or impl counts
  under "no test reaches" ([CLI](../CLI.md)).
- `impact`, `review` and `read --history` run git only to read the repository: they do not write
  `.git/index`, run no filter driver and, with git 2.44 or later, fetch nothing in a partial clone
  (an older git fetches what it lacks) ([SECURITY](../SECURITY.md#running-git)).
- `scrutate files QUERY [--limit N]` and the MCP tool `find_files`: the repository's paths ranked
  for a query that may be misspelt (`srch.rs` finds `search.rs`), then by frecency; no index
  needed, about 8 ms on this repository.
- `symbol` lists near matches when no definition has the name: names that start with the query,
  names whose first words its parts start (`BkSvc` finds `BookingsService`), then names that hold
  it (three characters or more), each saying how it matched (`match` in JSON, MCP and Python).
  `--exact` (MCP `exact`, Python `exact=True`) keeps only exact names. The language server's
  workspace symbols rank the same way ([CLI](../CLI.md#engine-b)).
- `search`, `symbol` and `refs` keep the files a glob (`-g`) or a type (`-t`) names, the files
  parsed as a language (`--lang`) and the definitions of a kind (`--kind`), and the MCP tools
  `search_code`, `find_symbol` and `references` take the same as `globs`, `types`, `langs` and
  `kinds`. A filtered search returns `-k` results whenever that many pass.
- Ranked search: field-weighted BM25 + exact lookup + semantic vectors (IVF) + LightGBM
  LambdaRank ranker (v8: better than v7 on held-out code in 56 of 58 cells, never worse beyond
  noise). The ranker is trained with documented types as answers too: a type is found from its
  documentation with MRR 0.478. `bench/retrain_ranker.sh` refuses a ranker that does worse;
  `bench/eval_sealed.sh` keeps a sealed hold-out ([QUALITY](../QUALITY.md)).
- Ranked search reads every line of an indexed file: code outside definitions is in 50-line
  windows, and a definition starts at its attribute lines (`#[get("/users")]` above a handler is
  found with it). A one-word query is looked up as a name, and a name typed with its punctuation
  is found by that name first (`search 'valid?'`, `search Get-Greeting`). Constants are symbols of
  kind `constant` that `symbol`, `outline`, `read_code` and `refs` find and ranked search never
  returns.
- Ranked search finds words of every script, scripts without spaces as character pairs; names
  compare in NFC (dependency `unicode-normalization`), and Traditional and simplified Han and
  Japanese shinjitai find each other (a Unihan 18.0.0 table and OpenCC ver.1.4.2
  `JPShinjitaiCharacters.txt`, Apache-2.0): `関係` finds `關係` and `关系`
  ([ARCHITECTURE](../ARCHITECTURE.md#tokens-textrs)).
- Vendored code ranks lower than the project's own in `search` and the MCP `search_code` by a
  fixed margin, so a clearly better vendored match still comes first, and it is never left out:
  `vendor/`, `third_party/`, `node_modules/`, `Pods/`, `Carthage/`, minified files and their kin,
  a subset of GitHub linguist's `vendor.yml`. A directory the root manifest builds as the
  project's own package (Cargo workspace members and path dependencies, a `go.mod` replace into
  the repository, npm, Yarn and pnpm workspaces) is not vendored. Every JSON item whose `path` is
  vendored code has `"vendored": true`, and text answers mark such paths without touching quoted
  code ([CLI](../CLI.md#engine-b)).
- Semantic vectors are stored as int8: the index about a fifth smaller, quality within 0.001 MRR.
  The bundled semantic model stores its word tables as int8 with one scale per row (7.6 MB in
  place of 14.6 MB) with ranking quality held (MRR@10 0.5873 to 0.5874). A model file named by
  `SCRUTATE_SEMANTIC` must be in this format, and one whose tables do not agree in size is
  refused ([QUALITY](../QUALITY.md)).
- A change of vector model remakes the vectors without rebuilding the index: back from
  `SCRUTATE_SEMANTIC=none`, 1.39 s of CPU here, 2.90 s on Guava ([ARCHITECTURE](../ARCHITECTURE.md)). A ranker whose
  features differ makes `search` fail saying so. The model signature is a hash of the model file,
  so a retrained model rebuilds the vectors.
- `refs` resolves each occurrence to its definition for Python, JavaScript/TypeScript, Rust, Go,
  Java, PHP, C, C++ and C#; `--def` keeps one definition and `--textual` gives every whole-word
  occurrence. `refs`, `callers`, `callees`, `deps`, `rdeps`, `dead`, `impact` and the language
  server take one decision per call site, so they agree ([CLI](../CLI.md#refs)):
  - Python, JavaScript/TypeScript, Rust and Go: receiver types from declarations (`x: T`,
    `x = T()`, `new T()`, `T::new()`, `T {}`), return types, fields, constructors, elements of
    lists, maps and tuples, closures, Go methods by receiver type and through embedded fields, Rust
    trait default methods, crate roots for binaries, tests, examples, benches and `build.rs`.
  - Java: packages, imports, members, nested and inner classes, records, method references,
    overloads picked by the argument count, fields and record components as symbols of kind
    `field`, enum and interface constants as constants.
  - PHP (`resolve/php.rs`): namespaces and `use`, classes, traits, `$x->m()` through the type of
    `$x`, `self::`, `static::`, `parent::` and `C::m()`, with names matched in any case where PHP
    does.
  - C and C++ (`#include` to repository files, namespaces and `::`, members of the class around
    and its bases, a header's declaration as the definition it declares) and C# (namespaces,
    `using`, aliases, typed locals, members, partial classes).
  - TypeScript and JavaScript imports through `paths`, `baseUrl`, `extends` written as a list and
    `${configDir}` (as TypeScript 5.5 reads them), and of a workspace package by its
    `package.json` name through `exports`, `module`, `main` or `index`. Import aliases, CommonJS
    `require` and `module.exports`, ES default imports and re-exports are followed.
  - An inherited method is the one the method resolution order reaches first, up to 8 levels; a
    `super` call is a decided call of the nearest base method, and `callers` of an override lists
    a call through its base type as undecided.
  - `callers` of a constructor lists the calls of its class (`Point(1)` for `Point.__init__`,
    `new Widget()`, `Invoice.new`). A call the resolver could not place, tied by its name only, is
    undecided.
  - In a language the resolver does not read, a use is tied to the one definition of its name it
    can reach, marked `(by name)`, and `refs` gives the reason `not resolved in this language`.
  - Fortran, Pascal, Ada and PHP functions match names in any case, as those languages do. Fortran
    needs a build with `--features extra-langs`.
  - Every reader of names takes a name's characters by Unicode's identifier rule (UAX #31), with
    the extra characters a language allows (`$` in JavaScript, Java and PHP, `'` in OCaml, F# and
    Haskell). `refs` finds a name in its composed and decomposed Unicode spelling.
  - Imports: Go through `go.mod`, an `#include "util.h"` beside the including file; config files
    are read only as regular files inside the repository of at most 1 MB. A relative import that
    climbs above the root resolves to no file. `rdeps` counts the unresolved imports that may name
    the file.
- Time and size limits of the resolver: `refs` through a typed variable, in one large function,
  where many blocks bind one name, and through a wide diamond of interfaces or base types takes
  linear time; a file past 2,000 levels of nesting is listed as too deep to read; `refs` counts
  every use on a line, and `--max-results N` counts uses; a use on a line longer than 400 bytes
  shows the part around it.
- `callers` asks the resolver about every call site, lists callers in path and line order and
  lists calls written outside every definition; `callees FILE:LINE` answers for such a line.
  `callers` and `callees` keep what they learned under `.scrutate/answers/` while nothing they read
  changes: `callers size` on Guava costs 1.4 s of CPU on a first run and 0.43 s after.
- Name lookup in `symbol`, `callers`, `callees`, `similar`, `refs` and `read_code` takes the name
  as typed first, then `Type::method` and generic owners, and orders namesakes; the C++
  `operator->` and `operator*` are found by name, and an explicit destructor or operator call is
  recorded, so `callers ~Shape` and `callers operator==` find it. A location (`path:start-end`)
  names exactly one definition in `symbol`, `callers` and `callees` ([CLI](../CLI.md)).
- Definitions and documentation: the comment above a definition is its documentation in many
  languages, past attributes and decorators; a documentation comment whose lines carry no comment
  mark (a GNU style C block, Lua `--[[ ]]`, Ruby `=begin`) is read; without a grammar a language's
  own comment marks are read. A method is named by its owner's bare type (`Box.put` for
  `Box<T>::put`). Many forms are definitions: Rust `mod`, `type` and `macro_rules!`, C++ methods
  declared in a class, C and C++ prototypes, functions assigned to names, members or table fields
  in Lua, JavaScript and TypeScript, Go type aliases, Haskell clauses as one definition, and more
  ([LANGUAGES](../LANGUAGES.md)). A `.h` file is parsed as C, C++ or Objective-C by its text,
  and a `.pp` file as Pascal or Puppet by its text.
- Calls are recorded under their definition's name (a trailing `?` or `!`, a prime, `r#`), inside
  Rust macro arguments, as turbofish calls (`f::<T>(x)`), and in more forms (PHP `?->`, Pascal and
  Verilog calls without parentheses, VHDL instances). A call matches a definition only in its own
  language family and by the name as written (`Ok(1)` is not a call of `ok`).
- `callers`, `callees`, `symbol`, `dupes`, `tsquery`, `read_code symbol`, `duplicates` and
  `structural_search` say when they stopped at their limit and which argument raises it; `symbol`,
  `callers` and `callees` take `--limit`.
- `dupes`: `exact` means the same body once whitespace is squeezed; `--threshold 1` prints the
  exact groups only; groups and their members are listed in one fixed order. `dupes` and `review`
  read the duplicate keys the index keeps for each definition.
- `similar` takes a window's location; on a constant it says constants are not compared.
- `tsquery` prints paths as `grep PATH...` does and names a missing path in a warning, exit code
  2; it decodes non-UTF-8 files, skips files over 1 MB, refuses an empty query and a predicate
  outside every pattern's parentheses, and does not parse a file that holds none of the strings
  every match of the query needs (`#eq?`, `#any-of?`). It caches each file's captures in
  `.scrutate/tsquery/`, keyed by content, so a repeated query parses no file it has seen
  ([CLI](../CLI.md#tsquery-cache)).
- `scrutate tsquery LANG QUERY [PATHS] --rewrite TEMPLATE` rewrites each match from a template of
  its captures and prints a unified diff; `--write` writes the files, only inside `--root`. No MCP
  tool rewrites ([CLI](../CLI.md#tsquery---rewrite),
  [SECURITY](../SECURITY.md#the-structural-rewrite)).
- Text index for repeated grep-style queries (`scrutate index --text`, `grep --index`): trigram
  postings whose output equals the walk's; incremental and safe for concurrent readers. Position
  masks in the postings bring the Linux tree's `kernel_thread` from 1,781 candidate files to 164;
  that tree's text index is 440 MB, a tenth of Zoekt's ([LEADERBOARD](../LEADERBOARD.md)). The format is 4; an
  index an earlier format wrote is rebuilt once ([ARCHITECTURE](../ARCHITECTURE.md)).
- UTF-16 files with a byte-order mark are transcoded and indexed. Chunk line numbers follow grep's
  line counting (`\n` only). Chunk text is cut at 32 KiB, and the definitions of one file share a
  text budget of 1 MiB plus 8 bytes per byte of the file, past which each keeps its first line: a
  one-line file of 8,000 nested functions indexes in 0.13 s with a 44 MB peak. Many sibling
  definitions or deep nesting index in linear time. A full index build of a C, Go or Java tree
  does not keep every syntax tree in memory.
- Lock files with an ordinary extension (`package-lock.json`, `pnpm-lock.yaml` and the like) are
  left out of the index like `*.lock`; `grep` still searches them. Inside a git repository the
  ignore files decide for `build`, `dist`, `target` and `venv`; `[index] exclude_dirs` in the
  root's `.scrutate.toml` (or `SCRUTATE_INDEX_EXCLUDE_DIRS`, where `\,` keeps a comma) leaves
  directories out for every front end. `[index] max_files` and `max_bytes`
  (`SCRUTATE_INDEX_MAX_FILES`, `SCRUTATE_INDEX_MAX_BYTES`) cap how many files, and bytes of them,
  each index holds; an update that would pass a cap stops with exit 2 and leaves the last index as
  it was. No cap by default ([CLI](../CLI.md)).
- What parsing makes of a file is an artifact kept by content (`artifacts.rs`), so a parsed and a
  stored file give the same index and vectors for another model need no parse; the store adds
  7.5% to `.scrutate/` here and 9.5% on Guava. An index built with older parsing rules rereads
  every file once ([ARCHITECTURE](../ARCHITECTURE.md)).
- A long-running index reparses an edited file incrementally for the 21 grammars without an
  external scanner.
- Reads and writes: a read never waits for another process's writer and answers from the last
  committed index. Each search, tool call and language server request reads the code index from
  one commit. In the MCP server, the language server and the Python bindings a read waits up to
  250 ms for the process's own update, then answers and says which changed files the answer does
  not hold yet (a line in the tool's text and `pending` in `structuredContent`, a language server
  log warning, a Python `UserWarning`) ([ADR 0002](../adr/0002-reads-during-a-write.md),
  [CLI](../CLI.md#the-index-directory)). `index`, `watch`, `serve --watch` and `reindex` wait
  for another writer for up to 10 minutes, or until cancelled. An update can be cancelled and
  rolls back, also when it panics.
- Damage: more kinds of damage are rebuilt, a writer stopped before its commit does not block
  later ones, a read-only index is answered as it is, and a search that meets a damaged segment
  rebuilds the index and answers. `check` notes each entry of `.scrutate/seg` no segment list
  names (a merge in progress or what a stopped writer left; an update removes it once it is older
  than 10 minutes), and reports segments whose vectors are missing or of the wrong width, or that lack the
  inverted-file lists their size calls for. A new
  segment's files are flushed to disk before the database names them; on macOS with a write
  barrier (`F_BARRIERFSYNC`), so the update behind a read of one changed file takes about 30 ms
  ([ARCHITECTURE](../ARCHITECTURE.md)).
- A fresh process opens an index whose database it saw pass a check as fast as a running one (the
  check runs once per state of the file, recorded in `.scrutate/checked`), and reads the index's
  statistics without counting the chunks table ([ARCHITECTURE](../ARCHITECTURE.md#storage-indexrs-lexrs)).
- A look for changes walks the tree once for both indexes, and `grep_code` and `references` read
  the text index for the files it holds as they are now: a rare word on 12,001 files takes 90 ms
  of CPU. On Unix a change of status time
  alone (a `chmod`) is seen; on Windows the indexes keep each file's status change time too.
- One session module (`session.rs`) holds a repository open for the MCP server, the language
  server, the bindings and `watch`, with reads side by side on up to 8 readers
  ([ARCHITECTURE](../ARCHITECTURE.md)). An index command uses the index a running
  `scrutate serve` holds open on the same root, through `.scrutate/session.sock` on Unix or a
  named pipe on Windows (owner only), with the bytes and exit code a fresh process prints; it never starts a server, and gives
  up a `serve` that takes no request for 2 s. `search` and the ranked part of `find` use it in
  about half the time or less. `SCRUTATE_NO_SESSION=1` turns this off; `SCRUTATE_SESSION_DEBUG=1`
  says why a call did not use one ([CLI](../CLI.md)).
- In a linked git work tree (`git worktree add`), the first lookup copies the main checkout's
  index and parses only the files that differ. Renames, copies and a branch switch and back parse
  no file the index has seen; nothing under the main checkout's `.scrutate/` is written (SQLite
  marks its read lock in `index.db-shm`, as for every reader).
- `scrutate watch` and `serve --watch` keep the indexes fresh as files change. They set the watch
  before the first update, use one inotify watch per directory on Linux (2 for a tree with an
  ignored `node_modules`), update a burst of saved files without a walk (one walk at most every 30 s), and on macOS follow
  FSEvents with file-level events, with a timer as the fallback. Directories that got no inotify watch on Linux are
  checked on a timer (1 to 30 s), and the message names `fs.inotify.max_user_watches` when that
  limit is the cause. A root replaced or renamed away and back is followed (`root replaced;
  watching the new tree`). A failed burst is tried again with a walk ([CLI](../CLI.md#watch)).
- The MCP server, the language server and the Python bindings watch a tree on a local disk, and a
  walk in the background finds a change that makes no event within 60 s, or 50 times what one walk
  takes when that is longer. On Linux and Windows each
  call looks only at the files the watch says changed since the last call, one `stat` each, and a
  cookie file keeps every write made before the call in its answer; on macOS every call looks at
  every file ([ADR 0001](../adr/0001-change-sets-and-the-cookie-barrier.md), [CLI](../CLI.md)).
- The JSON of the index commands is schema 2: `symbol`, `callers`, `callees`, `refs`, `outline`,
  `deps`, `rdeps`, `similar`, `dupes`, `read`, `search` and the ranked `find` print
  `{"schema": 2, "result": ...}` with `stopped_at` when the answer stopped at its limit; a `batch`
  record and the MCP structured result say `"schema": 2`. Engine A's JSON Lines and the
  error records are schema 1; `tsquery --json`, `check`, `stats`, `languages` and `config` print
  their own report, with no schema number ([CLI](../CLI.md)).
- `grep --max-bytes N` (`SCRUTATE_GREP_MAX_BYTES`, `[grep] max_bytes`) bounds a grep's text to
  whole lines with the `--offset` that continues (`--max-bytes 4000` prints 4,000 bytes or fewer).
- `grep --symbols` with a path argument finds the file by its path under the root. `find` lists
  the lines of its Engine A search in path order, takes a question with a space and a trailing
  `?` as words, and goes to ranked search when a regex-looking query finds nothing.
- `languages --json` lists every kind of definition the index gives a language and the extensions
  a language shares with another (`extensions_by_content`); `check --json` counts the indexed
  files and the constants.
- The models are trained on rows the engine writes (`bench/gen_features.py`,
  `bench/train_semantic.py`), and the benchmark builders and the ranker's trainer read the engine
  through the hidden `views` command ([QUALITY](../QUALITY.md)). `batch --features` names the
  features (`feature_names`).

### Product
- One binary: Engine A, Engine B, a CLI, an MCP server, a language server and Python bindings. The
  binary makes no network connections ([SECURITY](../SECURITY.md)).
- Unified `find`, MCP server (19 tools, and `edit_symbol` with `serve --allow-edits`), configuration files with environment-variable
  precedence, shell completions, progress reporting; errors as JSON records with `--json` or
  `SCRUTATE_DIAGNOSTICS=json`. A configuration file that does not parse is one line naming the
  file and the line, and a bad `.scrutate.toml` does not stop `--help`, `--version`, `config` and
  `completions`. On/off environment variables are off for `0`, `false`, `f`, `no`, `n`, `off` or empty,
  except `SCRUTATE_REDACT` (`off` or `on`) and `SCRUTATE_HOOK_BASH` (off for `off`, `0`, `false` or
  `no`);
  `NO_COLOR` turns colour off for any non-empty value.
- One definition of every index operation for the CLI, the MCP server, `batch` and the Python
  bindings (`ops.rs`), run through `Repo`; `batch` runs any operation by name, and reports a line
  that is not JSON and runs the rest. The command line, the language server and the tools turn
  paths into repository paths in one place.
- Commands run in a subdirectory use the index and `.scrutate.toml` above it, up to the top of
  the repository, so a nested clone or submodule does not use the outer index; `search --also`
  prints another repository's results by the path given. In the home directory or at a filesystem
  root with no index, a command that would build one stops with exit code 2 and names `--root` and
  `scrutate index` ([CLI](../CLI.md)).
- Ctrl-C stops a running update at its next batch of files, and a second Ctrl-C ends
  any command at once. Ctrl-C is handled through `signal()` / `SetConsoleCtrlHandler` directly.
- For AI agents: no MCP tool changes a source file unless the server is started with
  `serve --allow-edits` (`edit_symbol`), and every tool but `reindex` and `edit_symbol` is marked
  read-only (`readOnlyHint`); `grep_code` groups matches by
  enclosing symbol and searches the files the index holds; `references` resolves each use; an
  answer is at most 24,000 bytes by default (`max_bytes`) with the `offset` that continues it, as
  `--max-bytes` (`SCRUTATE_MAX_BYTES`) and `--offset` on the CLI; a capped answer holds the first
  matches in path order; a first index build blocks a tool call that sent no progress token for at most 20 seconds
  ([CLI](../CLI.md)).
- The MCP `grep_code` tool takes `mode` (`regex`, `literal`, `identifier`, `fuzzy`,
  `fuzzy_regex`, `pcre2`, with `max_edits`), `case` (`sensitive`, `insensitive`, `smart`),
  `word`, `path` and `globs`. `read_code` reads a whole definition with `symbol`, honours an
  explicit `end` and says where the rest starts, keeps at most 1 MB of line text, refuses a file
  with a NUL byte in its first 8 KB, and says `more lines follow` when a large file was not read
  to its end. The location at the start of every result (`path:start-end`) is accepted wherever a
  tool takes a symbol. `reindex` takes `force`; `search_code` takes at most 10 `alt_queries`.
- Every MCP tool but `edit_symbol` takes `response_format`: `detailed` (the default) or `concise`, which keeps every
  location and name and drops code, snippets and explanations; on this repository a concise
  answer is 5% to 44% of the detailed one. `serve --short-tools` (or `SCRUTATE_MCP_SHORT_TOOLS=1`)
  sends a short tool list with the same tools, arguments and checks: 5,657 bytes against 17,055
  when this was written
  ([CLI](../CLI.md)).
- MCP revision 2026-07-28 beside the handshake revisions; an `initialize` without a known
  `protocolVersion` is answered with 2025-11-25. `serve --structured` gives every tool an
  `outputSchema`, and a large answer pages in `structuredContent` too, with `offset`,
  `next_offset` and `total`. `notifications/cancelled` stops a call, and a `progressToken` hears
  the files read so far against the total during the first build, `reindex`, a large scan or
  `structural_search`. JSON-RPC answers as the specification says (-32700, -32600, -32601,
  -32602), notifications are never answered, a message is at most 256 MiB, and at the end of its
  input the server answers the calls in flight first. A tool argument of the wrong type is an
  error naming it, and tool errors say how to fix the call ([CLI](../CLI.md#serve-mcp)).
- An MCP answer checks the files it cites with one `stat` each and reindexes a changed one alone;
  without `--refresh-interval` the server scans at most a second apart. A tool call path that
  leaves the repository by its own parts (`..`, an absolute path elsewhere) is refused before
  anything is looked at, one that leads outside through a link counts as missing, and the index recovers from a
  corrupt database in every front end that stays open ([SECURITY](../SECURITY.md)).
- Secret-safe answers: the MCP tools, the Grep hook and `lsp` replace a secret in what they return
  with `[redacted:KIND]`, keeping the key name, URL scheme or PEM armour around it, and say how
  many they redacted. `SCRUTATE_REDACT=off` turns it off and `on` turns it on for the CLI's index
  answers; no tool argument turns it off. The detectors and what they cover are in
  [the table](../SECURITY.md#secrets-in-answers).
- `scrutate lsp`: a language server for editors; the VS Code extension starts it, JetBrains uses
  it through LSP4IJ. It answers every workspace folder from the index of its own repository and
  takes `workspace/didChangeWorkspaceFolders`; a file outside every folder's repository gets no
  answer. Go to definition names the definition the resolver picks, including the one a receiver
  call names (`o.valid?()` to `valid?`). It names files under the folder as the editor sent it,
  counts columns as the editor does, and works on a Windows share or in WSL
  (`file://wsl.localhost/...`). A request during the first build waits up to 20 seconds, then
  answers -32801 "the index is still being built". Editors opened on a folder below the
  repository top use the index at the top, through `scrutate config --json`
  ([CLI](../CLI.md#lsp)).
- `scrutate setup <claude|codex|opencode|cursor|gemini>` writes an MCP server entry that runs this
  binary into the agent's user file (or with `--project` the repository's), editing it in place;
  `--uninstall` restores it byte for byte, `--dry-run` writes nothing, `--instructions` adds a

- `scrutate setup claude --hook` installs `PreToolUse` hooks for Claude Code. The Grep hook
  answers Claude Code's Grep with Engine A's matches, bounded as an MCP answer is, also on Windows

  rule given only on Claude Code's command line or by an SDK host is in no file the hook reads

  (`setup codex --hook` writes `$CODEX_HOME/hooks.json`), puts `scrutate hook run --` in front of

  `rg` through `scrutate grep` with `rg`'s own output, runs `grep` and `find` as given, redacts
  secrets, and bounds the output to 24,000 bytes when no pipe takes it. It runs only flags on each

  [SECURITY](../SECURITY.md#setup-and-the-grep-hook)).
- On Unix `.scrutate/` is private to its owner (mode 0700). A `.scrutate` that is a symbolic
  link, or holds one (checked three levels deep), is refused, so nothing outside the repository is

### Platforms
A platform is supported only once its binary and wheel were built, installed and tested on it
([Install](../INSTALL.md#supported-platforms-010)). All six are supported:
- macOS arm64 (Apple Silicon; macOS 13 or newer, tested on macOS 27): built and tested natively;
  wheels `cp39-abi3` on CPython 3.10 to 3.13, `cp314t` on free-threaded 3.14.
- Linux aarch64 (glibc and static musl): built and tested in a clean container; the static musl
  binary prints byte-identical output; wheels `cp39-abi3` on CPython 3.10, 3.12 and 3.13,
  `cp314t` on free-threaded 3.14.
- Linux x86_64 (glibc and static musl): for the release commit the binary and its test binaries
  were cross-built on arm64 and 118 tests run in a `linux/amd64` container (behaviour, not x86
  speed); the same wheels as aarch64 ([Install](../INSTALL.md#supported-platforms-010)).
- macOS x86_64, Windows x86_64 and Windows ARM64: the Rust tests and a smoke test of the release
  binary pass on GitHub's runners, and the wheels (`cp39-abi3` on CPython 3.13, `cp314t` on
  free-threaded 3.14) were built, installed and tested there.
- The `-linux-gnu` archives need glibc 2.34 or newer (Debian 12, Ubuntu 22.04, RHEL 9 and later);
  the `-linux-musl` archives are static and run on any Linux.

### Known limits
See [RELEASE_READINESS](../RELEASE_READINESS.md) and
[SECURITY](../SECURITY.md#known-gaps-and-residual-risks).
- 0.1.0 is a verified first release for developer use. It is not declared production-ready for
  mission-critical environments.
- Windows and Intel macOS lack a benchmark run and a release archive built by the release
  workflow and installed on a machine. Linux x86_64 has no benchmark run, and no benchmark was
  measured on dedicated hardware.
- No independent security review: the security assessment is a self-assessment with fuzzing.
- The binaries carry no Apple or Windows code signature; the checksum and the attestation are the
  integrity check ([Install](../INSTALL.md#unsigned-binaries-on-macos-and-windows)).
- Publishing to PyPI, the VS Code Marketplace, Open VSX, the Homebrew tap and the Scoop bucket
  waits on the owner's accounts and repositories.
- Several machines sharing one index over a network file system is not supported.
- On macOS, every MCP, language server and bindings call looks at every file of the tree, since
  FSEvents can give a write a later event than the call's cookie.
- The `bench/agent_eval.py` agent evaluation has not run a round yet.
- Redaction shows a key body whole only when it is a DER public key (a PEM public key,
  certificate, request or revocation list): an OpenPGP public key block and an RFC 4716 SSH2
  public key come back with their bodies marked as key material
  ([SECURITY](../SECURITY.md#secrets-in-answers)).
